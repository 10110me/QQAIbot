# Design V2 对照与 0.3.0 实现说明

原始升级方案完整保存在 [design-v2.md](design-v2.md)，本文件区分已交付行为、受限能力与尚未完成的实机验收。**0.3.0 不等于原设计所有愿景已经生产验收。**

## 已交付的主链路

| V2 要求 | 0.3.0 行为 |
|---|---|
| 社交/工作分离 | app 负责 QQ 与控制平面，work-worker 独立进程负责模型生成/工作步骤，sandbox-worker 隔离执行代码 |
| 工作时不水群 | Presence 来自主任务状态；生成主动候选与 Outbox 发送前均检查，@ 和进度仍回应；后台研究不置主要工作忙碌 |
| 真实进度 | 注册表返回步骤、里程碑、通过/失败测试、更新时间、阻塞与陈旧标记；无可靠算法时估时为 null |
| 持久任务控制 | 创建、审批、拒绝、追加需求、暂停、继续、取消；版本检查、幂等命令、边界采纳和审计事件 |
| 任务恢复 | 短期租约、世代 fencing、过期中断记录；每个 generation 独立目录，源码/测试/成果检查点；恢复已有源码不重复请求生成模型 |
| 成功判据 | 有实际隔离测试报告、至少一个通过测试、无失败与有效成果才完成；同计划修复不允许移除或改写既有测试 |
| 完成交付 | Work 只写注册表，Social 经权限、来源撤回与复读静默检查后写入原有 Outbox；后端成果下载受 owner 鉴权和 SHA-256 校验 |
| 工作踩坑经验 | 保存失败、错误指纹、环境、测试结果、源码 manifest/Git 证据，修复后追加通过证据，只标该环境 verified_local |
| 群聊经验 | 需单独采集授权；识别报错候选，关联引用的方案和当事人明确反馈；没有具体方案时“解决了”也只记 resolved_unspecified |
| 经验检索 | 先按群/私聊/公共范围查询；关键词/错误指纹，显式授权后可用配置的 Embedding 做候选排序；匹配不代表根因确认 |
| 跨群复用 | 仅单独审核的去身份化派生经验/公开主张可跨群；不把来源群、原文或内部映射给聊天模型；发送前重查经验依赖 |
| 夜间研究 | 与基础日记忆解耦；仅研究获准外发的通用技术问题，按群/月/指纹缓存、独立每日预算与审计，不外发原始群聊/源码 |
| DeepSeek 流程 | 按本会话要求沿用网页研究与人工扫码，不默认替换为官方 API；网页失效等待人工/延后 |
| 来源与主张 | 受控下载实际 URL、保存 hash/时间/摘录；模型单独回答始终待审；人工核验需引用真实抓取摘录，发布另行明确选择，状态保留适用限制 |
| 复读静默 | 多用户相同消息只读检测；独立低权限 Token 接收外部 echo 状态、TTL 与冷却；发送前复核，绝不发送 +1/复读动作 |
| 后台 | AI 工作台、里程碑/测试/变化证据/下载、经验审核、夜间研究与主张核验；保留原有聊天评价、回放和其他模块 |
| 运维 | 普通/低内存模式保留；存储另行选择；新增 PostgreSQL V2 migration，备份命令及 4 核 8 GB/1 TB 指南 |

## 操作与权限

QQ：`/工作`、`/进度`、`/暂停工作`、`/继续工作`、`/取消工作`、`/追加需求`、`/经验反馈`。群内需 @ 或精确引用机器人。控制权要求同一发起人和原会话，不因为知道任务 ID 或是同一人在另一个群就披露私有进度。

全局后台只向 owner 开放新增工作/经验/研究入口；原有群范围 viewer/reviewer 不自动取得项目权限。当前没有项目协作者邀请系统、多租户服务或多管理员项目 RBAC，不能把这个后台当成公共 SaaS。

外部复读模块只应持有 `OSA_ECHO_TOKEN`，调用 `POST /api/v1/groups/echo-state`；该 Token 无法调用其他管理接口。没有模块时内建只读检测仍可用。管理员可在群策略设置 `echo_silence=false` 覆盖静默规则；模块不应拿管理员 Token。外部 TTL 最多 40 秒，追加 5 秒冷却，乱序/过期事件被拒绝或忽略。

新增后台可查看完整审核证据。对外发送和普通模型 RAG 仅使用经过作用域过滤的摘要，不暴露研究/经验私有来源映射。删除个人数据与撤回源消息会撤销对应衍生记录，并清理工作目录、向量字段与网页缓存删除队列；离线组件保留待清理标记。网站自己的聊天历史、已发 QQ 消息、独立备份仍需各自管理。

## 工作执行边界

执行器支持 Python 3.12 项目和附属静态文件，单个 bundle 最多 80 文件/500 KB、单文件 100 KB；内置 Python/numpy/Pillow/matplotlib，不动态安装第三方依赖。测试来自项目而不是模型声称“通过”；测试本身依然需要人审，尤其网页交互和复杂业务断言。

源码在 Work 的受控目录，不在主程序执行。用户代码在独立 Docker 容器，无网络、只读根目录、有限 CPU/RAM/PID/输出/超时，未获得模型/QQ/数据库密钥或 Docker Socket。受信任 controller 持有 Docker Socket，这是现有执行 Provider 的边界；它不是绝对隔离的微虚拟机，也没有宣称实现设计中的所有 VM 安全选项。

工作没有直接访问 NapCat；Social 没有访问 Work 模型会话。两者通过 PostgreSQL/受控 SQLite 注册表交互。SQLite 是兼容和离线测试后端；新 4C8G 安装推荐 PostgreSQL。生产注册表事务使用数据库锁与 fencing，当前面向单实例/少量 worker，不宣称分布式高吞吐或完整租户 RLS。

## 夜间研究如何闭环

1. 基础记忆巩固按既有授权完成，夜间研究独立排队。
2. 只有 `research_external=true` 的群才会为明确批准的通用问题或已知公开 Python 模块的去身份化错误创建研究。
3. 工作进程的研究循环沿用可见 DeepSeek 浏览器，不占用社交模型预算或主要工作 Presence。
4. 回答只形成待审主张；下载到相关页面也不会自动算验证。
5. 审核者先查看实际来源摘录，再提交该原文、hash、适用限制和原因。原文不匹配被拒绝。
6. 人工核验只标 `SUPPORTED_WITH_LIMITATIONS`，明确发布后才形成可供跨群检索的公共主张。源撤回/授权撤销时删除派生项。

目前没有把“自动语义核验、根因置信度、多个转载算独立证据”包装成已完成能力。无法可靠核验时保留 NEEDS_REVIEW 是预期行为。

## API 路径

为保留 0.2.x 工具任务兼容性，原 `/api/v1/tasks` 仍表示旧工具队列，V2 主要工作任务使用：

- `POST/GET /api/v1/work/tasks`
- `GET /api/v1/work/tasks/{id}`
- `POST /api/v1/work/tasks/{id}/commands`
- `GET /api/v1/work/tasks/{id}/events`（SSE，Bearer + Last-Event-ID）
- `GET /api/v1/work/tasks/{id}/evidence`、`/changes`、`/artifacts`、`/download`
- `GET /api/v1/agent/presence`
- `GET /api/v1/experiences`，`POST /api/v1/experiences/{id}/reviews`
- `GET /api/v1/consolidations`、`GET /api/v1/research/jobs`
- `POST /api/v1/research/jobs/{id}/retry`
- `POST /api/v1/research/jobs/{id}/claims/{index}/review`
- `POST/DELETE /api/v1/admin/kill-switch`

Kill switch 阻止领取新工作、请求取消未完成任务并暂停社交发送；删除开关不自动恢复社交发送，需显式使用原有恢复按钮。暂停/取消以实际状态为准，长原子步骤可能需要等待安全点或强制停止回执。

## 与设计愿景的差异及验收边界

本版沿用现有内嵌 WebUI，没有改成 Vue 3 构建链；主要任务没有通用 Shell/Node/npm/完整桌面 VM、自动网页功能验收、多租户 RLS、协作者项目 ACL、ANN 经验专用索引、自动 SQLite→PostgreSQL ETL 或强语义全自动事实核验。现有图片/音频/视频、文件、空间外部适配器、插件、评价回放等功能保留，仍需配置外部服务。

本地 SQLite 的注册表与模拟 Provider 工作流已测试；另有真实 Python 子进程运行测试夹具的 harness 检查。这不等于真实 Docker、QQ、DeepSeek DOM、模型生成质量或服务器压力验收。CI 增加 PostgreSQL 专用数据库测试与迁移步骤；当前会话尚未执行 CI。

版本交付应结合 [验证记录](public-release.md)，不能把设计中的 E2E-01～20 全部标为已通过。
